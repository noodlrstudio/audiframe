# audiframe — open application interoperability standard

**Product:** Noodlr Studio / open web music ecosystem  
**Status:** Proposed implementation specification; draft 0.1, targeting protocol 1.0  
**Date:** 10 October 2026  
**Proposed public repository:** `noodlrstudio/audiframe`  
**Companion:** [Noodlr Board integration and migration](./noodlrboard-audiframe-integration-product-spec.md)

## 1. Product decision and scope

audiframe is a host-neutral protocol through which an independently hosted web music application communicates with a host embedding it across an origin boundary. The application remains on its creator's website. The host and app exchange explicitly negotiated messages, without sharing JavaScript objects, application internals or an AudioContext.

Ship a small protocol, schemas, framework-independent TypeScript/JavaScript SDKs, conformance tools and examples. Noodlr is the first production host; Pulse is the reference application; WebAudioHub is an optional discovery registry. None is required to implement or use audiframe. The public repo is separate from WebAudioHub and Noodlr Board. This follows the later independent-repo decision in the source conversation, superseding its initial monorepo proposal.

**Normative language:** MUST/MUST NOT are implementation requirements for this proposed standard. SHOULD allows a documented reason to differ. All wire names, limits and release gates below are proposed design decisions, not claims that a released audiframe standard exists. Freeze schemas and fixtures before independent implementations start; change this document through RFCs when necessary.

### Relationship to existing efforts

| Effort | Existing role | audiframe relationship |
|---|---|---|
| WAM | Web Audio plugin modules, nodes, parameters and events | Complement; preserve WAM processing/event APIs behind an optional adapter |
| WebCLAP / WCLAP | CLAP plugins compiled to WebAssembly, browser/native hosting | Complement; do not redefine CLAP ABI, state or DSP |
| Wafer | Composable apps with same-origin iframe units and shared AudioContext | Learn from its app semantics; isolate a Wafer deployment behind an adapter |
| WAX | Browser applications in native plugin/DAW workflows | Prior art; potential host integration, no claim of wire compatibility |
| MIDIWebHub, Awesome WebAudio, W3C demo lists, existing Web Audio Hub resource repo | Discovery and resource lists | Cooperate, attribute and link; avoid claims that cataloguing is new |
| WebAudioHub | Proposed playable directory and compatibility registry | Optional consumer/publisher of audiframe metadata; catalogue other formats equally |

The sources in §17 support these distinctions. Do not repeat time-sensitive star counts, package versions or claims of unique novelty from the original conversation. Engage ecosystem maintainers through public RFCs; this spec does not authorize contacting anyone.

### Goals and non-goals

Goals: secure cross-origin host/app interaction; portable recall; MIDI and musical events; transport following; parameters; lifecycle; accessible embedding; explicit degraded operation; low adoption cost; independent implementations and adapters.

Non-goals for 1.0: DSP plugin format; browser DAW framework; arbitrary AudioNode routing; PCM over control messages; sample-accurate delivery guarantees; universal DAW offline rendering; remote code ingestion; replacing WAM, CLAP or Wafer; mandatory account, catalogue, CDN, payment, Noodlr branding or SDK. Ordinary nonparticipating sites remain embeddable subject to their own policies but are not audiframe-conformant.

## 2. Architecture and trust boundaries

```text
Host application -> host SDK -> authenticated MessagePort -> client SDK -> app
                      |                                  |
                  host policies                    app-owned state/DSP
                  MIDI routing                     app scheduler/audio
                  persistence                      standalone website
```

The window messaging bootstrap authenticates the two browsing contexts and transfers a dedicated MessagePort. All session messages subsequently use that port. Audio remains app-owned unless a separate native/plugin adapter provides an explicitly declared audio route. There is no assumption that both sides trust each other.

Core has no Svelte, React, Noodlr, cloud, WebMIDI, SharedArrayBuffer or cross-origin isolation dependency. Browser WebMIDI device permission and audiframe virtual MIDI routing are separate. Every embedding has a new random session identity; persistent app identity is distinct from host node IDs.

## 3. Bootstrap, negotiation and connection state

### Bootstrap messages (window only)

All bootstrap messages use `{channel:"audiframe", bootstrap:1, type, nonce, payload}`. `nonce` is a cryptographically random 128-bit-or-greater opaque string generated by the host; it is not an authentication secret. No board state, files, MIDI or credentials are sent before binding. Bootstrap schema limits: 16 KiB JSON, depth 16, string 2 KiB except documented manifest fields.

1. Host validates the configured HTTPS embed URL and exact expected origin, waits for iframe load, then sends `connect/offer` to that exact origin. Payload: `{versions:[{major:1,minor:0}], host:{id,name,version}, requestedCapabilities:string[]}`. Do not send internal board IDs or secrets.
2. App accepts only `event.source === window.parent`, a nonopaque HTTPS origin (localhost exception in development), valid schema and nonce. Its configurable `acceptHost(origin, metadata)` policy may accept any validated parent for low-risk features or restrict origins. This decision never gives the host ambient access to app files/devices.
3. App replies `connect/accept` to the observed exact host origin, echoing nonce. Payload: `{selectedVersion, app:AppManifest}`. If no supported version, reply `connect/reject` with `UNSUPPORTED_VERSION`; do not claim readiness. App chooses highest common minor within a supported major.
4. Host checks `event.source === iframe.contentWindow`, exact origin, nonce, selected version and manifest. It computes grants, creates a MessageChannel and sends `connect/bind` to that exact origin with exactly one transferred port. Payload: `{sessionId,version,grants,limits}`. App verifies the same parent/origin/nonce and the offered selection, rejects surplus ports, and closes duplicate bindings.
5. App sends session `session/ready` notification with `{acceptedGrants:string[]}` over the port. Host rejects capability claims outside grants. Both enter connected state; host then restores state before enabling performance traffic. An app can decline offered features and remain connected.

Host retries offers every 500 ms, at most six attempts per load; accepts only the first valid acceptance for the current nonce. Binding requires readiness within 2 s. Offer/accept are idempotent; SDK caches acceptance for the active nonce. Exhaustion produces `unavailable`, distinct from explicit rejection. User can retry. Any frame navigation/load, destruction, timeout during binding or peer disconnect invalidates nonce, pending requests, grants and port. New load means a new session; stale replies cannot mutate it.

Connection states: `idle -> offering -> binding -> connected -> restoring -> active`; failures lead to `unavailable`, `rejected` or `restore-blocked`. `suspended` and `closing` are session lifecycle states. `connected` does not mean audio unlocked or state successfully recalled. A top-level app with no parent stays standalone without throwing or disabling normal use.

## 4. Identity, capabilities and limits

Core capability IDs are immutable registry keys; capability version is independent of protocol minor version. Experimental asset grants use `x.org.audiframe.assets.read` / `x.org.audiframe.assets.write` until standardized; the unprefixed asset IDs in the inventory are reserved targets, not stable 1.0 grants.

`AppManifest` contains `id` (stable reverse-domain identifier), `name` (1–80 chars), `appVersion` (SemVer), `protocolVersions`, `capabilities`, optional `ports`, `stateSchemas`, `ui`, `links`, `extensions`. IDs are claims, not proof of domain ownership; hosts bind identity to the approved origin and embed URL. Ports have stable `id`, `label`, `direction:"in"|"out"` relative to app and `type:"midi1"|"event"`; max 32 ports. State schema descriptors contain `{schemaId, writableVersion, readableVersions:number[]}`.

Capabilities are versioned descriptors `{id,version:1,required?:boolean,options?:object}`. App advertises support; host grants an intersection of app support, host support, policy and user permission. Missing means denied. `required` expresses app requirements; either side may refuse an unsuitable embedding. A grant lists `{id,version,options}` and constrains direction, ports, ranges and quotas. Runtime changes can only narrow grants through `session/grants` notification; expansion requires a new negotiated session. App MUST cease revoked operations and cancel relevant queued work immediately.

| Capability ID | Meaning |
|---|---|
| `state.snapshot` | App snapshot and atomic restore |
| `midi.input`, `midi.output` | MIDI 1 short messages on specified virtual ports |
| `events.input`, `events.output` | Negotiated namespaced musical events |
| `transport.follow` | Host timeline snapshots and scheduled discontinuities |
| `transport.request` | App may request host transport changes, not dictate them |
| `parameters` | Discover/read/write stable app controls |
| `lifecycle` | Suspend, resume, dispose and performance policy |
| `ui.resize`, `ui.appearance` | Size requests, host viewport and presentation hints |
| `files.import`, `files.export` | User-mediated file transfer |
| `assets.read`, `assets.write` | Project-owned opaque asset storage; optional draft extension |

Core conformance requires bootstrap, envelope, errors and `lifecycle`; other features are optional independently testable profiles. A virtual MIDI grant does not grant hardware WebMIDI or SysEx. Microphone/camera, filesystem, clipboard, popups and browser downloads require independent browser/host permission.

Default negotiated ceilings: state 32 KiB; ordinary envelope 64 KiB encoded JSON; JSON depth 32; 128 pending requests; 256 MIDI/events per batch; 1,000 musical events/s sustained and 2,000 burst; 60 UI/parameter notifications/s; 10 state updates/s. State limit counts the entire state envelope; ordinary limit counts full wire envelope. Separate buckets prevent resize spam starving note-off. Host advertises equal or smaller event quotas if needed and may explicitly agree larger state limits. File quotas are separate (§10). Invalid or excessive traffic returns a bounded error or closes an abusive session; no unbounded queues. JSON sizes use UTF-8 `JSON.stringify`, not JavaScript string length; cyclic/nonfinite/non-JSON values are rejected before sending.

## 5. Session envelope and dispatch

```ts
type Version = { major: number; minor: number };
type Envelope = {
  channel: 'audiframe'; version: Version; sessionId: string;
  seq: number; // strictly increasing per sender, starts at 1
  kind: 'request' | 'response' | 'notification';
  type: string; // operation name; response echoes request type
  requestId?: string; // required for request/response, absent otherwise
  payload?: JsonValue;
  error?: { code: string; message: string; retryable: boolean;
            details?: JsonValue };
};
```

Only plain bounded JSON is permitted except documented transfer payloads. Requests/responses have unique request IDs per session. Response contains exactly one of `payload` or `error`; notifications cannot masquerade as responses. Version/session/sequence mismatch is rejected before dispatch. Reliable ordered port delivery supplies normal ordering; sequence identifies duplicate/stale sends. Never reorder operations to satisfy an old sequence. Unknown optional payload properties are ignored within negotiated minor version; unknown required discriminators/types fail. Validation must not merge untrusted objects into prototypes or execute strings/HTML.

Requests default to 2 s timeout; state restore 5 s, file chooser 60 s. Applications may explicitly negotiate stricter limits. Timeout settles locally and sends `request/cancel` notification `{requestId}`; late responses are ignored. Cancellation is best effort and MUST NOT imply an atomic operation rolled back. Mutating operations are serialized per state/parameter domain. Cache at most 128 completed request results for 30 s to make duplicate request IDs idempotent; any retransmission uses a fresh sequence number with the original request ID and identical payload, and a reused request ID with different content is rejected; do not retry mutations with a fresh ID automatically. Read operations can retry within policy. On disconnect reject all pending calls and remove listeners/timers/ports.

### Operation registry

| Type | Direction / kind | Request or notification payload -> response |
|---|---|---|
| `session/ready` | App -> host notification | `{acceptedGrants}` |
| `session/grants` | Host -> app notification | `{grants,reason}` narrowed full set |
| `session/ping` | Either request | `{sentAtMs}` -> `{receivedAtMs,sentAtMs}` in responder clock |
| `session/close` | Either notification | `{reason}`; release resources |
| `state/get` | Host request | `{}` -> `{snapshot,revision}` |
| `state/set` | Host request | `{snapshot,epoch}` -> `{revision,epoch}` after atomic apply |
| `state/changed` | App notification | `{snapshot,revision,epoch}` full bounded snapshot |
| `midi/batch` | Either notification | `{events:[{id,portId,data:number[],atMs?,routeId?,hops?}]}` |
| `events/batch` | Either notification | `{events:[{id,portId,eventType,data,atMs?}]}` |
| `transport/update` | Host notification | Timeline object in §8 |
| `transport/request` | App request | `{action,positionBeats?,bpm?}` -> `{accepted:boolean}` |
| `parameters/list` | Host request | `{}` -> `{descriptors,revision}` |
| `parameters/get` | Host request | `{ids:string[]}` -> `{values:[{id,value}],revision}` |
| `parameters/set` | Host request | `{changes:[{id,value}],atMs?,gestureId?}` -> `{values,revision}` |
| `parameters/changed` | App notification | `{values,revision,gestureId?}` |
| `parameters/gesture` | Either notification | `{id,gestureId,phase:"begin"|"end"}` |
| `lifecycle/set` | Host request | Lifecycle policy in §9 -> `{applied:boolean,audioStatus}` |
| `ui/resize` | App request | `{width,height}` -> `{width,height,accepted}` CSS px |
| `ui/viewport` | Host notification | `{width,height,devicePixelRatio,visible}` |
| `ui/appearance` | Host notification | `{theme,reducedMotion,contrast,accent?}` |
| `files/import` | App request | `{accept:string[],multiple:boolean}` -> `{files:FileDescriptor[]}` |
| `files/export` | App request | `{name,mimeType,size}` -> `{transferId}` |
| `files/chunk`, `files/finish` | Either request | §10 transfer payload -> bounded acknowledgement |
| `request/cancel` | Either notification | `{requestId}` |

Generate JSON Schemas for every row and golden success/error fixtures; this table is a required implementation inventory. Unknown requests return `UNSUPPORTED_OPERATION`, unknown notifications are ignored with bounded diagnostic counts. Extensions use `x.<reverse-domain>.<operation>` and explicit grants; core operation names are reserved.

## 6. State, revision and recall safety

```json
{
  "appId": "co.uk.5of12.pulse",
  "schemaId": "co.uk.5of12.pulse.document",
  "schemaVersion": 1,
  "data": {"example": "app-owned JSON"},
  "assets": []
}
```

This is the proposed standard snapshot envelope; `data` is opaque to the host. `assets` is omitted or lists only granted project asset references from §10. Protocol version, app release and state schema version MUST be independent. A host stores the envelope unchanged and restores only to matching app ID and approved origin. App authors own schema validation/migration, preserving source on failure. A new app version accepting old schemas is normal; host MUST NOT guess conversions or rewrite arbitrary state URLs.

App initialization MUST gate state publication, MIDI output and transport execution until the host completes restore or explicitly starts a fresh session. Host assigns an `epoch` string for each restore/fresh activation via `state/set` or, for a fresh session without saved state, `lifecycle/set` with `stateEpoch`. App emits only updates for that epoch; revision is a nonnegative monotonically increasing integer within it. State/get returns the current accepted revision. For no-state apps lifecycle activation still applies.

During restore the SDK queues edits or disables conflicting edits; app validates and constructs a detached candidate, prepares assets, then applies atomically. Success response occurs only after application; failure leaves the live state unchanged and blocks publication until retry or explicit fresh start. Restore stops playback by default and never activates devices. Host rejects old epoch/revision updates, and uses its document edit generation to prevent a late snapshot overwriting undo, node replacement or newer edits. Echoed restore acknowledgements are not dirty user edits.

State changes send debounced full snapshots (recommended 300–600 ms) and host may request a final snapshot before explicit save. Save waits for a bounded request then preserves last validated snapshot, reporting staleness if necessary. Unload/dispose cannot guarantee a fresh asynchronous response; periodic snapshots and host-owned persistence are required. Request completion means captured, not durably stored: host storage failure remains a host error and must not discard the last good snapshot. No blobs, base64 samples, tokens, device handles or runtime playing flags in ordinary state. Asset references must be durable before a snapshot referring to them is committed.

## 7. MIDI, musical events and routing

MIDI 1 short messages use complete packets, no running status: channel voice with correct 2/3-byte lengths and 7-bit data, plus negotiated supported system common/realtime short messages. Channel encoded in status is zero-based; SDK note helpers accept documented channels 1–16. Normalize note-on velocity zero to note-off in note helpers. Validate full status/length and byte ranges, including unsupported statuses. SysEx, MIDI 2/UMP and OSC are separate future profiles; reject rather than truncate. Port IDs must be granted and match direction.

`atMs` is host session monotonic time (§8), omitted means immediate. Late notes execute immediately within the negotiated tolerance; stale scheduled batches beyond 250 ms default are dropped, with note-offs/panic handled immediately. Bound future scheduling to 2 s by default. SDK reports scheduling quality; control-thread messaging provides best-effort timing, never sample accuracy. App schedules locally against its own audio clock where possible.

Each event has a unique ID. Hosts maintain bounded deduplication per route, use host-owned source identities and cap graph hops (default 8). App-supplied route IDs/hops are advisory and cannot bypass host routing policy. No implicit MIDI thru; explicit graph routes determine destinations. On disconnect, disable, grant revoke or transport stop, flush scheduled events and release active notes with targeted note-offs plus all-notes-off where supported. Note-off has queue priority. `events.*` requires negotiated event type schemas; unknown event types cannot turn into arbitrary RPC.

## 8. Transport and clock domain

Host is timeline authority. App can follow, or remain standalone if it cannot follow. `transport.request` is advisory and may be denied without changing app-owned patterns. Timeline update contains:

```ts
{ timelineId: string; discontinuity: number; state: 'stopped'|'playing'|'paused';
  capturedAtMs: number; effectiveAtMs: number;
  positionSeconds: number; positionBeats: number; bpm: number;
  timeSignature: { numerator: number; denominator: number };
  loop: null | { startBeats: number; endBeats: number } }
```

Beats are quarter-note units, zero at timeline start; seconds zero at start; BPM positive finite quarter notes/minute; denominator a supported power of two; position may be negative for pre-roll. App interpolates from effective position while playing. Increment `discontinuity` on seek, loop wrap or timeline reset; flush incompatible queued events. Host sends changes immediately and a 10 Hz default heartbeat while playing. Snapshots express a constant-tempo segment; send a new update for tempo changes, with no speculative tempo map in 1.0. Stop/seek must not restart the app unexpectedly.

Host clock is milliseconds from its `performance.now()` for that session; never compare raw child and parent `performance.now()` values. Use three `session/ping` exchanges: caller time t0/t3, responder receive/send t1/t2; estimate responder-minus-caller offset `((t1-t0)+(t2-t3))/2` and RTT `(t3-t0)-(t2-t1)`. Choose lowest RTT, refresh every 30 s and after resume; expose uncertainty at least RTT/2. App converts host timestamps using offset; map to app AudioContext time using a local measured clock pair. Host `audioTime` and native sample positions are not silently interchangeable. Throttling/drift falls back to immediate events or suspended following with a diagnostic; do not claim deterministic DAW timing.

## 9. Parameters, lifecycle and UI

Parameter descriptors align with WAM-style vocabulary: `id`, `label`, `type:"float"|"int"|"bool"|"enum"`, `minValue`, `maxValue`, `defaultValue`, optional `unit`, `step`, `choices:[{value,label}]`, `automatable`, `readOnly`. Values are finite numbers; bool is 0/1 and enum is a stable numeric choice. ID/value semantics remain stable across app releases or migrate explicitly. Describe at most 256 parameters; reject duplicate IDs or impossible ranges. List/read/write is optional. Batch writes validate all changes before applying atomically; reject out-of-range values rather than silently clamp. Response returns canonical values and revision. Changed notifications synchronize UI without feedback loops; revisions deduplicate echoes. Gesture begin/end supports recording; on timeout/disconnect end pending gestures. Scheduled writes have MIDI timing limits and MUST NOT advertise sample accuracy.

`lifecycle/set` payload: `{mode:"active"|"suspended"|"dispose", enabled:boolean, audible:boolean, midiOutputEnabled:boolean, visible:boolean, stateEpoch?:string}`. Host policies are independent of app's persisted musical content. Suspended/dispose stops new scheduling, releases notes, closes transferred resources and acknowledges best effort; disposal is idempotent. Host may remove an unresponsive frame after timeout. `audioStatus:"locked"|"running"|"suspended"|"unavailable"` is reported in acknowledgement; user activation inside the app may still be required. Muting app-owned audio relies on cooperative app behavior, not a security guarantee.

Host node mute/solo/arm/record logic derives these generic policies. Noodlr-only arm/record metadata belongs in a negotiated extension, never in mandatory core. Appearance is a hint; theme `light|dark|system`, reduced motion and contrast are semantic values, not arbitrary CSS or HTML. App can preserve its design language.

Manifest UI describes `{minWidth,minHeight,preferredWidth,preferredHeight,maxWidth?,maxHeight?,resizable:boolean}`. Resize requests are positive finite integer CSS pixels; host clamps to canvas/viewport and responds with applied size. App adapts to viewport; prevent resize feedback loops with equality checks and 100 ms coalescing. Host supplies accessible iframe title, keyboard focus entry/exit and external-open action; do not intercept typing shortcuts inside the frame. Apps provide semantic labels and reduced-motion support. Keep visible status sparse; diagnostics go in a developer inspector, tooltips and accessible labels. No mandatory toolbar, logo or debugging text.

## 10. Files and assets

Files are an optional 1.0 profile; project assets remain an experimental versioned extension until the reference implementation proves durable round-trip behavior. An app MUST operate with these capabilities denied.

FileDescriptor: `{transferId,name,mimeType,size}`. File imports require a host-owned chooser triggered by a current user action; no fabricated user-activation token. `files/import` may respond `USER_GESTURE_REQUIRED` when embedding/browser restrictions prevent opening. User cancellation returns `CANCELLED`. Export uses host confirmation/download after bounded transfer. Treat names as display names, never paths; reject traversal, executable auto-opening and HTML injection. Declared MIME is untrusted. No directory enumeration, arbitrary URL fetch, credentialed proxy or ambient filesystem access.

Default max file 16 MiB, aggregate 64 MiB/session, two concurrent transfers, chunks at most 256 KiB. `files/chunk` payload has `{transferId,index,byteLength,buffer:ArrayBuffer}` and exactly one matching transferable buffer; binary exception to JSON envelope size, checked before allocation/copy. Response `{nextIndex}` provides backpressure: at most one outstanding chunk per transfer. `files/finish` contains `{transferId,totalBytes,sha256}`; receiver validates count/digest then returns `{accepted:true}`. Cancel releases buffers; retry needs a new transfer or acknowledged index. Host stores only after complete validation, quota approval and atomic completion. No progress flood (max 10 Hz); chunks have independent sequence and session ownership.

Experimental `x.org.audiframe.assets` profile proposes `assets/put`, `assets/get`, `assets/release` using the same transfer machinery; snapshot references `{id,sha256,size,mimeType}`. Host returns session-scoped IDs then durable project IDs only after storage. Host authorizes reads to that project's explicit IDs, not arbitrary board assets. State binds stable IDs/digests, never blob URLs or expiring signed URLs. App must export import dependencies or explicitly declare nonportable external assets. Define GC, copy/share/remap and offline storage in each host before granting this extension. Do not advertise complete portability for legacy opaque state with external URLs.

## 11. Security and privacy requirements

- HTTPS in production; exact source/origin checks on every bootstrap message. Never use `*` for bind or sensitive data. Reject `null`/opaque-origin frames in core; a future native trusted-endpoint profile needs separate review, not a wildcard bypass.
- A received MessagePort is a bearer capability. Transfer only after authentication; never forward it or place it in app state. No origin field exists on port events, so validate session/schema/grants on every operation.
- Run untrusted apps on a different origin from the host. Minimum sandbox permits scripts and preserves app origin where required; do not use scripts plus same-origin permissions for untrusted host-origin content. Choose explicit `allow` Permissions Policy, no blanket microphone/MIDI/clipboard permission. Browser sandbox restrictions and protocol grants are independent controls.
- Host CSP restricts `frame-src`; app `frame-ancestors` may intentionally block embedding. CORS alone does not authorize embedding. Do not bypass X-Frame-Options/CSP or proxy third-party pages to gain same-origin access.
- App identity/manifests/catalogue metadata are untrusted text. No credentials, tokens, cross-board access, host DOM APIs or eval. Registry inclusion never grants runtime permissions. Narrow user permission UI to actual requested action.
- Rate limits, bounded parsers and backpressure reduce abuse; this protocol cannot prevent an app spending its own CPU or making its own network calls. Host can terminate the frame. Disconnect revokes port access but cannot retract copied bytes.
- Diagnostics redact snapshots, MIDI contents, filenames, URLs with query secrets and user identifiers by default. Telemetry opt-in; no central reporting requirement.

## 12. Error model and observability

Stable codes: `INVALID_MESSAGE`, `UNSUPPORTED_VERSION`, `UNSUPPORTED_OPERATION`, `CAPABILITY_DENIED`, `INVALID_PORT`, `INVALID_VALUE`, `STATE_TOO_LARGE`, `STATE_SCHEMA_UNSUPPORTED`, `APP_ID_MISMATCH`, `RESTORE_FAILED`, `STALE_EPOCH`, `ASSET_MISSING`, `QUOTA_EXCEEDED`, `RATE_LIMITED`, `USER_GESTURE_REQUIRED`, `CANCELLED`, `TIMEOUT`, `DISCONNECTED`, `INTERNAL_ERROR`. Include human-safe message, retryability and bounded optional details; never stack traces or raw state. Wrong-source messages are ignored, not answered. A valid denied request gets an error response. Malformed unsolicited traffic earns a bounded diagnostic; repeated violations close the session without amplifying traffic.

SDK exposes structured connection/error events and counters for dropped traffic, clock uncertainty and restore state. Host presents one calm actionable message when work cannot continue, with Retry/Open externally where relevant. Saved state survives any error. Error handling and state persistence are independently testable.

## 13. Interoperability and adapter contract

Adapters expose a descriptor `{adapterId,adapterVersion,sourceFormat,sourceVersion,mappedCapabilities,limitations}` and implement the same host-neutral operations. Declare losses before use. No mandatory registry admission or conversion to audiframe state for native-format hosting.

| Adapter | Initial map | Explicit limitation |
|---|---|---|
| Noodlr v2 | Manifest, short MIDI, opaque state, runtime, transport, appearance | No legacy restore ack; raw timestamps need normalization |
| Noodlr MIDI v1 | Note on/off, runtime, name | No inferred state, parameters or transport |
| WAM wrapper app | Parameters, serializable state, MIDI/events, transport if supported | WAM owns DSP/event graph within wrapper; remote host receives no AudioNode |
| WebCLAP wrapper app | Selected parameters/events/state via actual CLAP host | Binary CLAP state needs asset sidecar; no fake JSON coercion or ABI equivalence |
| Wafer wrapper app | Notes, clock, persistence, view where unit supports them | Unit hosted on wrapper origin; direct AudioNode graph stays there |
| Wafer host remote unit | audiframe control operations exposed as a Wafer unit | Remote audio graph composition unavailable without another explicit mechanism |

Each adapter has a source-version pin, capability matrix, fixture tests and upstream attribution/license review. WAM/WebCLAP/Wafer packages are optional dependencies isolated from core. Native hosts may provide separate audio capture/processing capabilities; label those as host-specific. A CLAP webview using its own plugin bridge stays on that bridge inside its wrapper; audiframe must not intercept it. Explore WebRTC/native capture only through separate RFCs with measured latency and permission behavior.

Files SHOULD stay below 500 lines; separate bootstrap, validation, state, clocks, routing, transfers and UI helpers. Client/host have no runtime UI dependency. Export ESM and types plus a version-pinned browser bundle for plain HTML; no required CDN. Bundle target <=15 KiB gzip per core host/client excluding optional adapters; measure in CI. Schemas are normative alongside prose; generated types must match. No hidden Noodlr imports.

SDK APIs are conveniences, not wire requirements. Client concept: `createClient({manifest,acceptHost,state:{get,set},midi,transport,parameters,lifecycle})`, `connect()`, `markStateDirty()`, `sendMidi()`, `requestResize()`, `dispose()`. Every asynchronous call has cancellation and typed errors. Handler wrappers enforce gate, epochs and validation even for app authors using small glue code.

Pulse reference must use actual Pulse code, not an unrelated mock. Preserve app identity `co.uk.5of12.pulse`, credit “Pulse · Chris Thomaidis”, and standalone behavior. Reuse its detached validation/migration and stopped restore. Its inspected bridge currently debounces state 600 ms, caps envelope at 32 KiB and advertises transport false; implementing transport/parameters requires real behavior before advertising.
